# Генератор сайтов для локального малого бизнеса

По JSON-брифу клиента одна команда собирает готовый, уникальный на вид сайт на Astro — для одного из 6 типов бизнеса: ресторан/кафе, автошкола, барбершоп, стоматология/медклиника, кофейня/пекарня, салон красоты.

## Быстрый старт

```bash
npm install
npm run new-site -- --brief=clients/briefs/demo-restaurant.json --type=restaurant
```

На выходе — собранный статический сайт в `sites/<slug>/dist`. Посмотреть локально:

```bash
cd sites/<slug> && npx astro preview
```

Готовые демо-брифы для всех 6 типов лежат в `clients/briefs/demo-*.json` — прогоните любой командой выше с соответствующим `--type`.

### Флаги

- `--brief=<путь>` — путь к JSON-брифу клиента (обязательный)
- `--type=<restaurant|autoschool|barbershop|dental-clinic|bakery|beauty-salon>` — тип бизнеса, должен совпадать с `business_type` в брифе (обязательный)
- `--dry-run` — принудительно использовать черновой контент без обращения к Claude API
- `--seed=<строка>` — переопределить seed для выбора дизайна (по умолчанию берётся из `brief.seed`, а если его нет — из названия клиента)
- `--regenerate-content` — принудительно заново вызвать Claude, даже если бриф не менялся с прошлого запуска (по умолчанию при live-генерации результат кешируется в `clients/generated/<slug>/content.json` и переиспользуется, пока бриф не изменится — это экономит вызовы API при повторных запусках/передеплоях)

## Генерация текста через Claude API

Без ключа пайплайн работает в **dry-run режиме**: текстовые поля собираются из брифа напрямую (без ИИ) и помечаются `[ЧЕРНОВИК]`, чтобы было видно, что их ещё не вычитал Claude. Это позволяет проверить дизайн и сборку сайта бесплатно и без сети.

Чтобы включить реальную генерацию текста:

1. Получите ключ на [console.anthropic.com](https://console.anthropic.com) → API Keys.
2. Скопируйте `.env.example` в `.env` и впишите `ANTHROPIC_API_KEY=...`, либо экспортируйте переменную в окружении перед запуском:
   ```bash
   export ANTHROPIC_API_KEY=sk-ant-...
   npm run new-site -- --brief=clients/briefs/demo-restaurant.json --type=restaurant
   ```

Промпты лежат отдельными редактируемыми файлами в `packages/content-gen/src/prompts/*.md` — их можно править без изменения кода.

## Приём брифа от клиента

Отдельного инструмента для сбора брифа нет: когда приходит новый клиент, соберите JSON-бриф (по образцу `clients/briefs/demo-*.json`) из того, что прислал клиент, сохраните его в `clients/briefs/`, и запустите `new-site`. Формат брифа описан в `packages/content-gen/src/schema.ts` (`BriefSchema`).

Отдельно стоит спросить у клиента ссылку на его профиль в Google/Яндекс Картах (поле `reviews_url` в брифе) — если она есть, на сайте появится кнопка «Оставить отзыв», ведущая туда. Сайт статический и не хранит новые отзывы у себя — писать и хранить отзывы должна площадка, которой люди и так доверяют (Google/Яндекс), а не форма на никому не известном сайте.

### Дополнительные блоки под конкретный бизнес

Кроме общих полей, в брифе есть необязательные поля, которые включают блоки, специфичные для типа бизнеса — если их не заполнить, соответствующий блок просто не появится на сайте:

- **`team`** — команда (имя, роль, фото, короткое био). У каждого типа бизнеса своё название и оформление: «Наши инструкторы» у автошколы (круглые аватары), «Наши мастера» у барбершопа (крупные фото с подписью), «Наши врачи» у стоматологии (карточки с квалификацией).
- **`process_steps`** — пронумерованные этапы процесса. «Как проходит обучение» у автошколы (горизontальный маршрут с пунктирной линией), «Как мы работаем» у пекарни (вертикальная лента).
- **`faq`** — частые вопросы, раскрывающийся аккордеон (сейчас есть у стоматологии).
- **`stats`** — короткие цифры доверия вида `{ "value": "12 лет", "label": "на рынке" }` (у ресторана и барбершопа).
- **`highlights`** — отдельно выделенные хиты меню/продаж с фото, отдельно от полного списка `menu_or_services` (у ресторана и пекарни).

Если каких-то из этих данных у клиента нет — не страшно, генератор просто не покажет блок, для которого нет данных (проверяется по факту наличия данных, а не наугад).

## Повторные правки

Если клиент просит поменять текст, фото или контакты — отредактируйте его бриф и запустите `new-site` ещё раз с тем же именем клиента. Сайт в `sites/<slug>/` уже существует, поэтому скрипт **не** пересоздаёт код страницы — обновляются только данные (`src/data/site.json`, `src/data/site-config.json`), токены дизайна и фото, после чего сайт пересобирается. Ручные правки, которые вы могли внести напрямую в файлы конкретного сайта, не затираются.

## Деплой

Пока не подключён — сборка доходит до локального `astro build`. Место под будущий шаг деплоя уже оставлено в `cli/new-site/src/steps/` (по аналогии с `buildSite.ts`), когда определимся с хостингом.

## Структура репозитория

```
packages/
  shared-ui/          # общие Astro/Preact-компоненты (Button, Nav, Lightbox, BookingForm, ...)
  variance-engine/     # seed → детерминированный выбор design tokens + вариантов секций
  content-gen/          # zod-схема брифа, санитизация, вызовы Claude API + dry-run, промпты
  templates/
    restaurant/ autoschool/ barbershop/ dental-clinic/ bakery/ beauty-salon/
      manifest.ts        # какие секции есть у этого типа бизнеса и сколько у них вариантов
      tokens.ts           # 5 готовых наборов design tokens
      sections/            # Astro-компоненты секций (2-3 варианта вёрстки на каждую)
      astro-project/        # копируемый скелет Astro-приложения
cli/new-site/            # CLI-пайплайн (валидация → дизайн → контент → фото → сборка)
clients/
  briefs/                 # JSON-брифы клиентов (в т.ч. 6 демо)
  generated/               # кеш сгенерированного через Claude контента, по клиенту, чтобы не гонять API повторно
sites/                    # ВЫХОД: собранные Astro-проекты, по одному на клиента
```

Все секции вёрстаны mobile-first на Tailwind (`sm:`/`md:`/`lg:` префиксы): сетки на мобильном сворачиваются в одну колонку, шапка сайта на мобильном превращается в бургер-меню (`shared-ui/src/components/Nav.astro`, без JS — на чистом CSS через скрытый чекбокс), формы и таблицы цен не переполняют экран. Проверено скриншотами на вьюпорте 390×844 (iPhone) для нескольких шаблонов и вариантов секций.

Как устроена вариативность — подробнее в комментариях `variance-engine/src/select.ts`: для каждого клиента детерминированно (по seed) выбирается набор design tokens, состав опциональных секций (галерея/отзывы включаются не всегда) и вариант вёрстки каждой секции, плюс лёгкая перетасовка порядка секций. Один и тот же бриф всегда даёт один и тот же сайт; разные клиенты почти гарантированно получают разные комбинации.

## Как добавить новый тип бизнеса

1. Создайте `packages/templates/<новый-тип>/` с той же структурой, что и у существующих типов:
   - `src/manifest.ts` — список секций, количество вариантов, обязательность/вероятность (см. `restaurant/src/manifest.ts` как образец).
   - `src/tokens.ts` — 4-5 готовых наборов design tokens (используйте те же CSS-переменные, что и в `shared-ui/src/types.ts` → `DesignTokens`).
   - `src/sections/` — Astro-компоненты секций. Переиспользуйте `Hero*`, `About*`, `Gallery*`, `Reviews*`, `Contact*`, `Footer*` из любого существующего типа почти без изменений (они не завязаны на конкретный бизнес) — под новый тип обычно нужно написать только «основной» раздел (меню/услуги/программы) и, по желанию, 1-2 уникальных блока для этого бизнеса (команда/этапы процесса/FAQ/цифры/хиты — см. раздел про дополнительные блоки выше). Не копируйте чужой `TeamSection`/`ProcessSection` один в один — сделайте свою визуальную подачу, иначе шаблоны снова начнут выглядеть одинаково.
   - `src/index.ts` — барrel-экспорт `manifest` и `tokenSets`.
   - `astro-project/` — скопируйте скелет из другого типа и замените в `package.json` и `src/pages/index.astro` все упоминания старого имени пакета (`@sitegen/template-<старый-тип>`) на новое, поправьте `sectionComponents`/`NAV_LABELS` под id вашей «основной» секции, обновите `src/styles/tokens.css` (дефолтный набор) и `src/data/site-config.json` (плейсхолдер).
2. Добавьте новый тип в `BusinessTypeSchema` в `packages/content-gen/src/schema.ts` и в `BUSINESS_TYPE_LABELS` в `packages/content-gen/src/generate.ts`.
3. Добавьте пакет в `PACKAGE_NAMES` в `cli/new-site/src/utils/templateRegistry.ts`.
4. Добавьте `"@sitegen/template-<новый-тип>": "*"` в зависимости `cli/new-site/package.json`, запустите `npm install` в корне.
5. Добавьте демо-бриф в `clients/briefs/` и прогоните `new-site`, чтобы проверить сборку.
